# jobsadmire.com rebuild + Operations "Website" CMS module — programme plan

Status: **v3 for owner approval** (v1 → 3 adversarial reviews → v2 → 6-lens premortem → v3) · Author: Fable 5.1 · 2026-09-18
Scope: three repos (jobsadmire-website, jobsadmire-operations, jobsadmire-crm), Vercel, GitHub, VPS deploy scripts.

**What the premortem changed (read first).**

1. **Two launches instead of one.** Phase A puts the new site live on the imported design-package content with a minimal lead-capture door, about four weeks in. Phase B cuts the same site over to the CMS behind a flag. A slipped CMS can no longer hold the site hostage, which is exactly how the February CMS died: finished in seven days, never deployed, never populated.
2. **The two live apps are protected before the first Operations push.** The Ops deploy pipeline starts the new container _before_ it migrates and has no lock or failed-SHA block (the CRM's has both); a boot-time throw in a new module would crash-loop production. WP0 fixes the pipeline, adds a module kill switch, isolates the website's Redis use, and monitors both apps.
3. **Every alarm leaves the VPS.** Site health lives on Vercel and is watched by an external monitor to your phone; a synthetic lead runs every 30 minutes; a missing daily digest is itself the alarm; a second human is a fallback recipient.
4. **Content is a dated lane, not an open queue.** Every owner input carries a decide-by date and an auto-default; the marketing team are the named editors; counsel is engaged in WP0; a scope ladder and a stop rule replace "we'll polish until content arrives".
5. **The candidate pool launches aggregate-only** (live counts and facets from the Portal); per-profile cards come later, only after partner notice and partner-set consent. Proof scans, representatives and the blog editor move to v1.1 so the identity-bearing pipeline is built with real material and a rehearsed takedown, not under launch pressure.
6. **Live-site safety in WP0:** the existing Vercel project is left untouched (a second project is created), secrets are inventoried and rotated rather than blindly revoked (the old site's only working intake runs on one of them), and the GSC/GA/Ads baseline is exported _before_ the redirect map is decided.

### 3.1 Website (jobsadmire-website)

- **Routing:** `app/[locale]/(site)/…` (14 pages, careers detail, legal, thank-you, newsletter routes); `proxy.ts` = CMS redirects → next-intl (explicit matcher); `generateStaticParams`; ISR tags (`site:${locale}`, `page:${slug}`, `blog`, `pool`, `openings`, `stories`, `sitemap`) **and** time floors (D8); representatives single-record view `no-store`.

## 12. Stop rules and scope ladder

- **Gate A stop rule:** two consecutive weekly "no" answers to "can Phase A be public this week?" → the programme cuts to Phase A only; Phase B becomes a separate dated engagement.
- **Content stop rule:** two consecutive weeks with zero newly completed content tasks while code commits continue → all build work halts except launch-blocking defects; descend the ladder (pool cards → representatives → proof images → blog editor → newsletter → CRM feed).
- **Budget stop rule:** cumulative agent-days > 1.5× the phase estimate → descend the ladder before any further building.
- **Counsel trip-wire:** no engagement by WP0 end → D14 minimal set; newsletter and pool cards off for Phase A.
- **Stack trip-wire:** D5 spike red after day 1 → Next 15 + next-intl 3.
