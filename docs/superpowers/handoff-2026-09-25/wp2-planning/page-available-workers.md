## traps
- The page's copy promises live data in five places (hero badge, stats strip, FAQ 211, pool CTA 071, sticky 048) but the prototype is 100% static with an inline 12-record fixture and no feed; Phase A has no live source at all (CRM website-feed and Ops pool service are unbuilt) — do not ship 'Live'/'Updated weekly' over static numbers.
- `pool` is FIXTURE_ONLY: importing the 12 JS records into the LOCAL bundle's collections makes production throw (assertServableInProduction); keep them in a dev-only fixture.
- Design `person` ≠ door `name`; design `city` is not a catalog field — the door drops unknown keys silently (no 400), so a naive port loses the city.
- Do not reuse `state.lang` semantics: the prototype couples the site language switcher to the candidate Language filter.
- Design analytics pushes candidate refs/trade/country — D13 allowlist forbids candidate refs; route every event through src/analytics/track.ts.
- Two FAQ answers and the 'Days 1–3'/'Weeks 4–8'/'CV & photo on request'/'{n} ready now'/'Showing X of Y matching'/'{n} active'/'Load more profiles (N more)'/'selected' labels are not in the catalogue — reserve sys.* ids (D7) rather than typing English.
- availworkers.231 'more)' and 232/233 'profile(s) attached' are sentence fragments built by concatenation in JS — restructure as ICU messages, not fragment joins.
- The four legacy 'hire-workers-in-turkey' links and the crm.jobsadmire.com/ext-login links are old-site URLs; routing.ts owns /hire-workers and settings.portal owns the portal host.
- Success must navigate to /tesekkurler?form=workers (typed FormKey) — the inline 'Request sent' panel is the design's WhatsApp-mock artefact.
- Nav order in this page's desktop nav (7 links) differs from the README's 11-item order and label ('Candidates' vs 'Available Workers') — the shared chrome, not this page, decides.
- Desktop values in the inline styles are 1.333x authored (zoom 0.75 at ≥1101px); ≤1100px values are 1:1 — normalise per D19, never mix.
- The SSS `sec` group contains four form placeholder ids (144, 145, 151, 152) mis-sectioned as FAQ — a bulk APPROVE by sec would sweep them in.
- WP2 must retry POSTs on any non-2xx and expect `replayed: true` on an identical payload within the hour; a FAILED status still returns 200 with a visitor-safe `error` to display.
