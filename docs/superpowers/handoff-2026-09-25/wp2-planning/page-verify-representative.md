## traps
- Do not build the register or the record dialog on the 70 staff-data strings (verify.148-197, verify.240-259): they are static translations of sample rows, and FIXTURE_ONLY_COLLECTIONS refuses a representatives collection in production — Phase A is an empty state by decision (D23, §10 row 11).
- Do not render 'Register last updated: <today>' — the design substitutes new Date() when registerUpdated is empty; D17 requires dated claims from data or hidden.
- Do not default an unknown status to 'Authorised' (design meta() fallback) — fail closed.
- Do not turn the fraud report into WhatsApp-only: the copy promises 'we act on every report and tell you what we found' — wire formKey `fraud` (description min 20, evidenceKeys ≤3 via the upload route) with WhatsApp as co-primary fallback; success must go to /tesekkurler?form=fraud (D13).
- Do not push rep_id / since:'Jan 2022' to the dataLayer (D13 allowlist; identifiers forbidden).
- Do not load flags from flagcdn.com or fonts from Google at runtime (spec §3.1 local flags / next/font).
- Do not port the printBadge document.write popup as-is (unescaped CRM strings, literal PHOTO box); badge printing belongs in Operations (v1.1 stable public id).
- Do not copy the JSON-LD FAQ text from the design's <script type=ld+json> — it differs from verify.101-108; build FAQPage from the same strings via faqJsonLd.
- Do not treat the two crm.jobsadmire.com hosts in the design (feed + ext-login) as canonical — the bundle's portal host is portal.jobsadmire.com and the website never calls the CRM (Ops proxies via CrmClient).
- Do not rely on the design's 'Show 2 more red flags' CSS — it hides only one flag (nth-child(7) is the button).
- Do not leave verify.050/verify.119 with literal '{{ queryEcho }}' / '{{ lastUpdatedLabel }}' tokens — use the fragment ids (verify.235/236, verify.238) or interpolate.
- Do not put a second unlabeled search input in a sticky bar without a label/aria-live (D20).
