# WP2a — Website foundation for the page ports — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the fourteen designed pages of jobsadmire.com everything they consume before the first page is ported: a forms kernel that talks to the Operations intake door (server action → `postForm` → `/tesekkurler?form=<key>` or the visitor fallback panel), the Phase A data layer emitted by the importer (metrics, rate config, roles, countries, offices, sectors, blog index, page SEO records, all nav groups) with the D17 numbers-are-data lint armed, route groups so legal/thank-you/portal pages get the right chrome, per-page header CTAs, the OG image route, per-locale alternates and the Article/JobPosting JSON-LD builders, the primitive extensions, shared blocks and client islands the pages share, build-time assets (sourcing map SVG, flag sprite, QR, brand files) so no page fetches anything at runtime, the gate tooling (one route list, launch profile, placeholder counter, JS ceiling, pixel harness), the pure calculator engine shared by the homepage teaser and the Cost Calculator page (W2/W24) — plus the small additive Operations catalog extension (`city`, `track`, `topic`, `portfolioUrl`) the page forms need.

**Architecture:** Everything stays inside the WP1 shape: package strings through `makeT`, composed copy through `sys.*` in `src/messages/{tr,en}.json`, data through the importer into the LOCAL bundle (the frozen `contract/` is untouched — collections are already `Record<string, Record<string,unknown>[]>`), server components by default with `'use client'` islands loaded by `next/dynamic` where heavy. Forms are React 19 server actions built by one factory (`createFormAction`) over one server-only transport (`postForm`, one retry, 8 s budget) and one client shell (`FormShell`: honeypot, Turnstile, consent, submit, fallback panel). Route groups `(site)`/`(minimal)`/`(bare)` select the chrome; per-page CTAs and detail-page alternates are derived from the pathname and the emitted hreflang tags, never from props. The gate keeps one route list, the 204,800 B script ceiling, the launch profile and the D27 pixel harness.

**Tech Stack:** Next 16.3.5 (App Router, RSC, server actions, `next/og`), React 19, TypeScript strict, Tailwind 4, next-intl 4.14.5 (`as-needed`, TR root), Zod 3, Vitest 4 + Testing Library, Playwright + axe + Lighthouse CI, `tsx` scripts, `qrcode`, `pixelmatch`; Operations side NestJS 10 + jest.

**Spec:** `docs/superpowers/specs/2026-09-18-website-programme-design.md` (approved v3; §3.1 Website, §5 WP2, D5, D7, D11, D13, D17–D21, D26–D27). **Rulings:** `docs/superpowers/plans/2026-09-20-wp2-rulings.md` (W1–W57; they supersede the spec's letter where they say so and R1–R60 of the WP1 rulings where they cite them). **WP1 rulings:** `docs/superpowers/plans/2026-09-18-wp1-foundation-rulings.md`.

## Global Constraints

- `npm run verify` (tsc, eslint, prettier --check, vitest) must be green at EVERY commit — it runs inside the Vercel build; a red commit is a red preview.
- Never import `design-package/**` or `src/content/local/*` from `src/**` (R56/D23); `scripts/` may. `src/content/local/*.json` are generated by `npm run content:import` and never hand-edited. The frozen contract `contract/website-bundle.v1.ts` is not modified (hash-pinned; Ops vendors it).
- Package strings only by exact id through `makeT`/`t()`; every new copy is a `sys.*` key present in BOTH `src/messages/tr.json` and `src/messages/en.json` (W9/W23); never invent a package id; never read `sys.*` through `t()`.
- Server-only secrets: `OPS_WEBSITE_WRITE_TOKEN`, `OPS_WEBSITE_TEST_TOKEN`, `OPS_API_URL` are read only in `server-only` modules; the browser never calls Operations (D6); no CORS change.
- Accessibility over pixel fidelity (D20): real inputs with labels and `role=alert` errors, focus management, reduced-motion fallbacks, contrast tokens; the width sweep (1440…390) and axe stay at zero on every gate route.
- JS: `resource-summary:script:size` ≤ 204,800 B on every gate route (W13 amended); heavy islands load on interaction/viewport via `next/dynamic`.
- No runtime fetch to any third party except GTM/Turnstile (W14): maps, flags, QR, fonts, logos are local or build-time.
- Website `main` is currently the production branch of the live Vercel project: all WP2 work lands on `wp2/foundation` (previews only); nothing is pushed to `main` until the owner has moved the production branch (memory note 2026-09-20).
- Operations `main` is production in ~2 minutes; the one Ops task ships behind the still-off `WEBSITE_MODULE_ENABLED` flag, with the WP3a push recipe (`docs/DEPLOYMENT.md` § Flipping / § Deploy pipeline), boot conformance at 0 and `PERMISSION_KEYS_HASH` untouched.
- One heavy job at a time on this machine (`jest --maxWorkers=2`, one `next build`, one Playwright run); reviews may run in parallel.
- Task order: 1 data layer → 2 forms kernel → 3 chrome → 4 SEO → 5 primitives/blocks → 6 islands/assets → 7 gate tooling → 9 calculator engine → 8 Operations catalog (the Ops task runs last because it deploys to production and needs its own worktree, W47); Tasks 1–7 and 9 are serial on `wp2/foundation`.
- Every task updates the docs it touches in the same commit (ARCHITECTURE, CONTENT-MODEL, SEO, ANALYTICS, INTEGRATIONS, DEPLOYMENT, PRD) — the website `CLAUDE.md` checklist applies.
