## traps
- makeT throws in dev for an unknown id — an id typo fails the page locally but silently renders '' in production; test ids against src/content/local/catalogue.json before shipping.
- Button/NavLink internal hrefs are cast to Href and passed to next-intl's typed Link: a '/'-rooted href that is not a pathnames key (e.g. '/hire-workers#form' or a route not in the table) bypasses typing — verify next-intl's behaviour for anchors/query on typed pathnames before using them in CTAs.
- The absolute 184,320 B script assertion leaves only ~11.8 KB headroom over the 172,509 B shell — the documented '+25 KB per page' watch is looser than what the gate actually enforces; a heavy calculator island can trip it.
- Sitemap already lists 15 unbuilt routes per locale (they 404 via [...rest]) and /blog is listed + in Footer/SlimBar although the plan keeps /blog out of nav/noindex until 6 TR bodies; decide build-vs-NOINDEX_PATHNAMES before Gate A's crawl.
- openGraph.images points at a non-existent /opengraph-image.png on every page — add the next/og route or a static file early; PageSeo.ogImage in the bundle must be an absolute URL.
- localeAlternates emits the same slug for both locales; on blog/careers detail (per-locale slugs, D16) this produces wrong hreflang unless overridden; LanguageSwitcher/LanguageHint likewise fall back to the parent index (R58) and have no prop to receive a real alternate.
- SiteChrome variant='minimal' cannot be selected per page — the layout mounts default chrome for everything; legal + thank-you pages currently show SocialRail + WhatsAppFab. Needs a foundation change (route group layout or page signal) first.
- Replacing the spike home/hire pages breaks e2e/routing.spec.ts (hire-h1 text 'tr'/'en', home link text 'hire') and possibly seo.spec.ts's one-h1 rule — rewrite those assertions in the same change.
- New routes in pathnames must pass redirects.test.ts (no live route inside a 410 prefix, no redirect `from` colliding with a live path) and routing.test.ts (unique TR slugs).
- The hamburger/desktop-row threshold is xl=1101px (R46, WP1-only); the pixel-comparison pass must move it to lg=901px by shrinking nav type/padding — the width sweep at 1100/900 will catch overflow.
- LanguageHint (z-55, lg+: bottom-4 centred) overlaps a page-mounted StickyCtaBar (z-50, bottom-0) on desktop, and WhatsAppFab (z-40) sits under the bar between lg and xl — decide stacking before mounting StickyCtaBar on real pages.
- src/lib/calculator/ does not exist despite ARCHITECTURE § Calculator engine describing it; the Cost Calculator page and the homepage teaser must build it (RateConfig with effectiveFrom/reviewDueAt, D17) and route every figure through formatTRY.
- Never import design-package/** or src/content/local/* from src/** (lint error, R56/D23); page collections/page records must come via the importer into the bundle, and pool/stories/representatives must stay empty under LOCAL in production (assertServableInProduction fires on Vercel previews too).
- sys.* keys are only what src/messages/{tr,en}.json carry — every form label/error/placeholder WP2 needs is new sys.* copy in BOTH files; the package ships zero of it. Never reuse a package id and never read sys.* via t().
- No form handler / server action pattern exists in the repo; WP2 defines postForm from scratch against the Ops contract (server-only, OPS_WEBSITE_WRITE_TOKEN, honeypot + Turnstile, dedupe-aware, visitor fallback panel with prefilled wa.me link, redirect to /thank-you?form=<FormKey>).

- docs/PRD.md line 118 wrongly says BreadcrumbList/FAQPage builders don't exist — do not re-create them; update the PRD in the same change set (CLAUDE.md checklist item 3).
