## traps
- consentVersion is REQUIRED on every submission (DTO has no @IsOptional) even for forms whose design has no consent checkbox (Homepage hero form) — pick one site-wide version string ≤40 chars and always send it.
- Top-level envelope is forbidNonWhitelisted: any extra key beside locale/consentVersion/captchaToken/honeypot/sourcePath/fields is a 400 before the catalog runs; inside `fields`, unknown keys are silently dropped instead — so a mis-spelled field name loses data with no error.
- Design forms vs catalog field-name mismatches: the door requires `name` on every INQUIRY/CALLBACK/VISIT/CALCULATOR key, but the design's Homepage lead form has `person` OPTIONAL and no `email`; Hire Workers quick-quote has no person/name; the Contact callback has only phone+day+slot; the office-visit widget has no name/email/phone. WP2 must add those inputs (design delta) or the door 400s. Design names must be remapped: person→name, count→headcount, timeline→startWhen, roles→roleNeeded (hire) / trade (workers, calculator), detail→message, need→message, dial+phone→phone.
- `city` appears on Homepage, Hire Workers, Partner (HR agency), Available Workers and Contact designs but exists in NO inquiry catalog entry (only `careers`) — it is dropped silently; fold it into `message` or ask Ops to add it.
- `partner` requires `country` (iso2) but the HR-agency variant of the design form collects `city` (Turkey implied) — send `country: 'TR'` for that variant; the institute/sourcing variants collect a free-text country that must be converted to ISO-2 before sending ('Turkey' is a 400 'must be a two-letter ISO code').
- Join Our Team speculative application has no openingSlug/CV; `careers` requires both. Route it through `contact` with iAm='job_seeker' (and subject) or drop it — decide before building the page.
- Newsletter key answers 404 'This form is not accepting submissions.' until the operator flips isActive (D14, SQL on the VPS); with the website showing the form, every real signup returns 404 → don't treat this 404 as an outage in the fallback panel/alarms.
- Captcha asymmetry: if the website ships without a Turnstile site key but Ops has its secret configured, every write-class POST without captchaToken is a 403 (missing-input-response is a visitor-side failure). Test-class calls without a token skip verify — so a passing synthetic lead does NOT prove the visitor path works.
- Dedupe is on (formKey, isTest, honeypot, locale, sorted fields) per clock hour — sourcePath is NOT hashed, so varying only sourcePath does NOT defeat the replay; a monitor must vary a `fields` value. Conversely a legitimate retry after a 502 with the identical body lands on the same row (replayed: true) — treat replayed as success.
- Careers cvKey: upload-cv builds the key from the multipart filename's extension; a filename without `.pdf` yields `careers-cv/<uuid>` which fails the catalog pattern → 400. upload-cv checks the client-declared mimetype (not sniffed) and returns a public-looking `url` — never use/expose that url (private bucket in prod, 403).
- status FAILED is HTTP 200: a careers apply refused by residency/closed opening or a required PublicApplyDto rule arrives as 200 + status 'FAILED' + non-null `error` — the website must inspect `data.status`/`data.error`, not just the HTTP status, before redirecting to /tesekkurler.
- A 429 body carries `fallback: 'whatsapp'` and `reason: 'tripped'`; the Ops-side contract says the website's visitor panel reads `fallback` — parse the JSON body of the 429.
- Newsletter routes run for real under the test token (no token-class read) — never point a smoke test at a real subscriber token; and the confirm token is one-shot-ish (second click → ALREADY_CONFIRMED) so the page must POST only on a visitor click, never on page load or prefetch (link scanners).
- Module-flag-off is a bare 404 identical to an unknown route; the website cannot distinguish 'door dark' from 'form key unknown' from 'newsletter inactive' by status alone — read the message string or the ping first.
- Every Ops deploy is a 30–60 s 502 window on /api/website/*; retry bounded within the server action then show the fallback panel — a persisted retry queue on Vercel is forbidden (D11).
- X-Website-Visitor-Ip must be a bare valid IP (first comma segment is taken, validated with isIP); pass the visitor's address from the request headers, never the Vercel egress; UA is truncated to 500.
- Fraud evidence route rejects any non-file multipart part (fields: 0) — send ONLY the `file` part, no extra text fields; HEIC is refused by the sniffer; sends 3 separate calls, not a 3-file multipart.
